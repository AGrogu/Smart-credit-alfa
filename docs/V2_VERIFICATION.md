## Что реально проверено в предметной области

- Аннуитет, корректировка последнего платежа, сумма тел=P, календарные месяцы от исходного числа, даты 31 января/февраля/марта, HALF_UP.
- Категории A/B/C отдельно от решения; отсутствие автоматического отказа по C; помесячный стресс/ликвидность; сезонный средний коэффициент не дает автооффер.
- FIX-B сначала проверяет 18, затем 24 месяца, не переписывает 12 месяцев в запросе; точные проценты 806 719,03 ₽.
- Два согласия и подтверждение прогноза; подготовитель не отправляет/не подписывает; чужой клиент не получает файл/карточку/организацию; демооператор не одобряет и не читает финансовый пакет.
- Неизменяемые версии файла, замена пяти месяцев на шесть, адресное уточнение и новая ApplicationVersion; произвольный PDF требует аналитика.
- Классификация H: сырые 30 млн остаются в исходном файле; после подтверждения 3 млн переводов, 2 млн кредита и 1 млн депозита покупательские поступления — 24 млн.
- Атомарное назначение аналитика, запрет положительного решения при недостаточном потоке; отдельный обоснованный экономический отказ G.
- Устаревшая revision/hash оффера/комплекта, истечение оффера/полномочия, изменение календаря до принятия, отсутствие подписи/денег по старым условиям.
- Активация ВКЛ без выдачи; R→P; два конкурентных запроса по 800 тыс. не создают 1,6 млн; повтор не зачисляет второй раз.
- ACT/365: частичный возврат 103 945,21 → 100 тыс. тела; затем 506 575,34; проценты 10 520,55. Оплата одних процентов не восстанавливает лимит.
- Ограничения траншей, пять минут quote и конфликт версий; обновление устаревших проверок; просрочка/блокировка, долг после истечения, полное закрытие.
- Разовая наступившая строка 189 119,19: проценты 40 тыс., тело 149 119,19; все 12 строк закрываются без копеечного долга.
- Новый расчет автоматически включает внутренний действующий договор, даже если клиент стер старые платежи; canonical ID не дублируется.
- Общие поступления и расходы организации проводятся один раз при нескольких договорах; оценка линии включает обязательства других договоров. Противоречивые общие потоки требуют уточнения. Старые исполненные события распознаются без повторного зачисления. Это проверено четырьмя отдельными регрессиями.
- Внутреннее обоснование банковского аналитика и причины отзыва не попадают в клиентскую карточку/список; банк сохраняет доступ к внутреннему обоснованию. Отдельная API-регрессия проверяет отсутствие закрытого текста.
- Сессия истекает по реальному бездействию независимо от демочасов. Продвижение часов блокируется при SIGNED или незавершенных денежных резервах; отмена SIGNED до захвата задания сохраняется без выдачи.

Браузерные сценарии нового модуля: полный разовый путь, полный путь линии до частичного возврата, подготовитель/планшет. Остальные перечисленные ветки проверялись API/чистыми алгоритмами; их прохождение через каждую комбинацию экранов не объявляется выполненным.

## Воспроизведение

```bash
./scripts/check.sh
APP_PORT=8084 docker compose -p smart-credit-qa -f docker-compose.yml -f docker-compose.test.yml up --build -d --wait app
# Один раз создать отдельную тестовую БД, если ее еще нет:
docker compose -p smart-credit-qa exec db createdb -U credit credit_qa
APP_PORT=8084 docker compose -p smart-credit-qa -f docker-compose.yml -f docker-compose.test.yml --profile test run --build --rm api-tests
```

Для полного UI-прогона используйте отдельный **чистый** QA Compose project с собственным volume: новые кредиты предыдущего прогона намеренно становятся существующим долгом и меняют следующую оценку. Не сбрасывайте данные основной демонстрации ради зеленого теста. Финальная UI-проверка использовала `smart-credit-v2-final3`, порт 8088. Команда:

```bash
APP_PORT=8088 docker compose -p smart-credit-v2-final3 -f docker-compose.yml -f docker-compose.test.yml --profile test run --build --rm e2e
```

После UI-прогона на этом же отдельном QA выполнено:

```bash
.venv/bin/python scripts/verify-v2-restart.py --url http://127.0.0.1:8088 --project smart-credit-v2-final3
```

Последняя строка показывает конкретный локальный macOS runtime проверки; на другом компьютере используйте его обычную конфигурацию Docker. Скрипт разрешает только явно названный localhost QA-проект `smart-credit-v2-*`; данные не удаляются. Во время restart сервис кратковременно недоступен.

## Что остается ограничением

Это существенная рабочая доработка кредитного домена, а **не заявление о полной приемке всех AT-01–24 и NFR ТЗ**.

- Не измерены 1000 заявок / 10 пользователей / p95, холодный запуск на эталонных 4 CPU/8 ГБ, полный failover и аварийное убийство процесса ровно посередине COMMIT. Успех денежной транзакции и повторов проверен; это не заменяет промышленное нагрузочное испытание.
- API использует общие `/commands` и JSON-агрегаты; буквальные URL/таблицы каждого пункта ТЗ не воспроизведены. Worker встроен в API, claim обеспечен транзакционной блокировкой вместо отдельного сервиса с lease timestamp. Общая блокировка часов ограничивает масштабирование.
- Подбор сохраняет механизм и описание в заявке, но не реализует полный отраслевой опрос/портфель альтернатив из исследования. Формы и банковская очередь не прошли пользовательские интервью; причинный эффект UX не измерен.
- Нет отдельного конструктора произвольных внешних обязательств и универсального редактора нормализации источников; известный seed-долг и внутренние договоры учитываются сервером, новые заявленные платежи не могут уменьшить известный долг. Для сложного несопоставленного обязательства нужен дальнейший предметный интерфейс.
- Документный manifest — имитация содержательной проверки опубликованного синтетического набора. Он не проверяет подлинность настоящего файла. Антивирус/OCR и реальные реестры/БКИ не подключены.
- Не выполнены все UI-сочетания уточнения/отказа/исчерпания выдачи, полного долгого сопровождения множества траншей и всех конкурентных гонок. Финальная неуспешная выдача и технический retry реализованы, но полноценный сценарий остановки worker на каждом промежуточном статусе требует отдельной приемки.
- Не проверены Safari/Firefox/Windows/x86, доступность с screen reader и полноценный focus trap диалогов; проверены Chromium и адаптация 768 px.
- События сохраняют ID, автора, доменное/реальное время и payload, но полная схема аналитики/causation_id и отдельная продуктовая воронка ТЗ не реализованы.
- GitHub-публикация, выдача доступа жюри и публичный хостинг не выполнялись без отдельной авторизации. Локальный архив и Git bundle не заменяют обязательную GitHub-ссылку при соответствующем правиле сдачи.

Никакие тесты на синтетике не подтверждают настоящую PD, безопасность банковского запуска или достигнутое снижение дефолтов. Все реальные финансовые, правовые и интеграционные вопросы перечислены в исходном исследовании и не подменены выдуманным банковским правилом.
