# Сценарии проверки

Этот файл — план и ожидаемые результаты. Выполнение и ограничения среды фиксируются отдельно в [VERIFICATION.md](VERIFICATION.md); наличие сценария здесь не означает, что он успешно выполнен.

Используйте только синтетические данные локального приложения. Пароль демо-аккаунтов — `Demo2026!`. Для повторной демонстрации создавайте новые заявки; не удаляйте данные ради повторного прогона.

## Сквозные ветки

| ID | Действия | Ожидаемый результат |
|---|---|---|
| E01 | `good@demo.local`: открыть подготовленный черновик → отправить → принять → подписать → выполнить демо-выдачу | `approved → accepted → signed → disbursed`; сохранены условия, сумма и уникальная ссылка на выдачу |
| E02 | `risk@demo.local`: отправить; затем изменить финансовые поля в новой заявке и отправить её | Отказ из-за серверных результатов проверки; плохая история не исчезает от редактирования клиентских финансов |
| E03 | `info@demo.local`: отправить неполную заявку → в ответе указать выручку и пояснение | `needs_info`; сообщение доступно клиенту; после ответа процесс продолжается, ответ сохранен |
| E04 | `review@demo.local`: отправить → войти как `bank@demo.local` → открыть очередь и заявку → добавить заметку → одобрить с причиной | `manual_review`; банк видит риск и проверки; ручное решение сохраняет автора и основание |
| E05 | `offer@demo.local`: отправить запрос 4 500 000 ₽ → изучить измененные условия → принять | `alternative_offered`; предложение отличается от исходного запроса, расчет соответствует предложению |
| E06 | `retry@demo.local`: отправить → повторить проверку после ошибки | `check_failed`, затем продолжение; нет вечного «обрабатывается» и нет дублей заявки |
| E07 | `good@demo.local`: создать новую заявку через каталог, пройти шаги, загрузить TXT/PDF, сохранить и обновить страницу | Серверный черновик, введенные данные и документ доступны после обновления и повторного входа |
| E08 | Одобрить заявку → отклонить предложение клиентом; отдельный черновик отменить | Терминальные `declined` и `cancelled`; дальнейшие несовместимые действия запрещены |

## Права и защита данных

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| S01 | Без сессии запросить список, карточку или документ | 401; содержимое не возвращается |
| S02 | Под сессией компании A запросить UUID заявки и документа компании B | Доступ закрыт; подмена идентификатора не раскрывает содержимое |
| S03 | Предпринимателем вызвать ручное одобрение, банковскую заметку, сводку или аудит | 403 либо иной недоступный ресурс; состояние не меняется |
| S04 | Сравнить банковское и клиентское представление одной заявки | Во втором нет `risk`, `checks`, `recommendation`, `notes`; внутренняя заметка не попадает в историю/уведомления |
| S05 | Выполнить изменение без CSRF или с чужим CSRF | 403; данные неизменны |
| S06 | Несколько неверных паролей подряд для локального тестового логина | Ограничение частоты входа; пароли отсутствуют в логах |
| S07 | Загрузить файл >5 МиБ, исполняемый файл, HTML, подменённый тип, опасное имя | Сервер отклоняет содержимое/размер; допустимое имя не управляет серверным путем; скачивание attachment |
| S08 | После выхода повторить защищенный запрос со старой сессией | Сессия недействительна |
| S09 | Изменить профиль после отправки заявки | Снимок компании в отправленной заявке остается прежним |

## Финансы, состояния и конкурентность

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| B01 | Рассчитать обе продуктовые линейки на граничных суммах/сроках | Корректная Decimal-арифметика, две цифры после запятой; вне лимитов — ошибка |
| B02 | Сопоставить равный риск при разных продуктовых правилах | Риск и решение — разные результаты; продуктовые лимиты учитываются отдельно |
| B03 | Повторить создание и значимое действие с тем же `Idempotency-Key` и телом | Одна сущность/операция, безопасный ответ на повтор |
| B04 | С тем же ключом отправить другое тело | Конфликт; исходная операция не заменяется |
| B05 | Выполнить несовместимые действия с одной версией заявки | Одно действие фиксируется, другое получает конфликт; не возникают два финальных результата |
| B06 | Дважды запросить выдачу, в том числе с разными ключами | Единственная запись выдачи; повтор/недопустимое состояние не создаёт новую |
| B07 | Пропустить этап: из draft сразу sign, из rejected accept, bank action без причины | Сервер блокирует переход/неполное решение |
| B08 | Уточнить сведения после `needs_info` | Новый ответ и обновленный снимок основания соответствуют новому решению, прежняя история не исчезает |
