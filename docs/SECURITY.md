# Безопасность и эксплуатационные ограничения

Это локальный демонстрационный стенд с известными тестовыми паролями. Он не подготовлен для публичного размещения или обработки реальных банковских данных. Проверки безопасности ограничены его собственными синтетическими данными.

## Реализованные границы

- Пароли хранятся как salted scrypt: `N=16384, r=8, p=1`, 32-байтовый результат; сравнение через `hmac.compare_digest`.
- Сессионный токен генерируется случайно, в БД хранится SHA-256 токена. Cookie `credit_session`: `HttpOnly`, `SameSite=Lax`, 12 часов. `Secure` включается настройкой при HTTPS; для localhost HTTP по умолчанию выключен.
- Изменения с аутентифицированной сессией требуют `X-CSRF-Token`; дополнительно сервер отклоняет сторонний Origin. Выход удаляет серверную сессию.
- Лимиты попыток входа сохраняются в БД: окно 15 минут, отдельно учетная запись и IP. Ошибочный пароль не откатывает счетчик; успешный вход сбрасывает счетчик учетной записи.
- Владелец заявки определяется сессией и `company_id`, а не присланным клиентом идентификатором компании. Чужая заявка/документ недоступны. Права банка проверяются в API.
- Клиентский JSON не содержит внутренние проверки, риск, рекомендацию, историю оценок и заметки. Причина окончательного решения и запрос сведений предназначены клиенту; сотруднику следует писать их как сообщения клиенту. Внутренняя заметка хранится отдельно.
- Для полей используются Pydantic-ограничения, запрещены неизвестные поля. Идентификаторы серверные; финансовые значения ограничены, не принимают NaN/Infinity и лишние десятичные разряды.
- Файлы: PDF, UTF-8 TXT, PNG, JPEG, максимум 5 МиБ и 20 документов на заявку. Проверяется базовая сигнатура/кодировка; имя генерируется сервером. Файл хранится в БД и выдается как attachment с `nosniff` после проверки прав. HTML/исполняемые расширения не разрешены.
- Значимые изменения, аудит, уведомления и идемпотентность сохраняются транзакционно. Версии и блокировки препятствуют конфликтующим решениям.
- Ответы API имеют `Cache-Control: no-store`; добавлены CSP, `nosniff`, запрет встраивания во фрейм и идентификатор запроса. Логи включают метод, путь, код и request ID, без паролей и тел документов.

## Что не реализовано

| Ограничение | Последствие / следующий шаг |
|---|---|
| Известные демо-аккаунты, нет регистрации, MFA, восстановления пароля и проверки полномочий | Для внедрения нужен отдельный IAM, политика доступа и управление жизненным циклом учетных записей |
| Локальный HTTP и нет управляемого TLS | Перед любой разрешенной публикацией нужен HTTPS; `COOKIE_SECURE=true` |
| Базовая проверка сигнатур файлов, без антивируса/CDR | Файл может содержать вредоносный контент при валидной сигнатуре; принимать только синтетические тестовые файлы |
| BLOB в БД; нет шифрования на уровне приложения и политик retention | Для реальных документов нужны шифрование, KMS, сроки хранения и процесс удаления |
| Нет нагрузочных испытаний, горизонтального масштабирования и внешнего rate-limit gateway | Пределы производительности и поведение нескольких экземпляров не подтверждены |
| Аудит хранится в той же БД, доступной приложению | Он не является неизменяемым регуляторным журналом; нужны отдельное хранение и контроль целостности |
| Нет автоматизированного backup/restore, мониторинга SLO и аварийного восстановления | Сохранность после штатного рестарта не заменяет проверку восстановления из резервной копии |
| Нет реальных проверок KYC/AML, БКИ, реестров и модели финансового риска | Демонстрацию нельзя использовать для настоящих кредитных решений |
| Лимитер входа работает по адресу соединения | За reverse proxy требуется доверенная схема определения IP; не доверять произвольному X-Forwarded-For |
| Локальный SQLite сериализует записи | Это удобный режим разработки, не доказательство эксплуатационных свойств PostgreSQL |

Полный перечень выполненных и непроведенных испытаний — [VERIFICATION.md](VERIFICATION.md). Тест-план — [TEST_SCENARIOS.md](TEST_SCENARIOS.md).

## Данные, секреты и публикация

В репозиторий входят только исходники и синтетические fixtures. Локальные базы, виртуальное окружение, node_modules, логи, browser-state и `.env` не должны коммититься. `.env.example` содержит только настройки и демонстрационные значения. Реальные банковские данные и личные файлы пользователя не нужны.

Обычный stop/start не должен удалять БД. Команды удаления volumes или базы являются разрушительным сбросом и должны быть отделены от запуска; их не нужно выполнять для показа новой заявки. Публичное развертывание, публикация GitHub и выдача доступа требуют отдельного разрешения пользователя.

## Аналитика при установке зависимости

При обновлении Swagger UI обнаружена транзитивная npm-зависимость `@scarf/scarf` 1.4.0 с установочной аналитикой. В логе первоначального `npm install` подтверждён запуск её `postinstall` (`node ./report.js`). Полных сетевых журналов этого запуска нет, поэтому нельзя подтвердить или исключить передачу установочного отчёта. Проверенный код этого установщика формирует сведения о дереве зависимостей и установке; сам факт сетевой отправки не установлен. Это ограничение проверки приватности, а не доказательство отсутствия передачи.

Зависимость полностью удалена из `package.json`, lock-файла и Docker-сборки. Поставляются только статические браузерные файлы Swagger UI 5.34.0, LICENSE/NOTICE и лицензии включенных компонентов; происхождение и SHA-256 записаны в `SWAGGER_PROVENANCE.json`. Пакет получен через `npm pack --ignore-scripts`, его установщик не запускается при сборке решения. Для будущих установок добавлены `scarfSettings.enabled=false`, `SCARF_ANALYTICS=false` и `DO_NOT_TRACK=1` в команды/образы проекта. Приложение не содержит внешней аналитики; E2E перехватывает и запрещает запросы к внешним origin.
